# 클라이언트 네트워크 기반

## 연결과 수명

- `UGameNetworkSubsystem`이 게임 인스턴스 초기화에서 연결을 시도한다. 맵 전환으로 연결을 다시 만들지 않는다.
- `Client/Config/DefaultGame.ini`의 `[/Script/ThatsMine.GameNetworkSubsystem]`에서 숫자 IPv4 주소, 포트, 연결 제한 시간을 지정한다. 이름 조회는 하지 않는다.
- 연결 대기는 게임 진입 초기화 단계에서 지정된 시간(기본 3초, 최대 30초)까지만 수행한다. 연결 실패 시 상태를 제공하고 게임 초기화는 계속된다.
- `should_connect_on_initialize_=False`이면 자동 연결 시도를 생략하고 `Connect`로 연결할 수 있다. 자동 재접속은 하지 않는다.
- TCP 연결 성공을 확인한 뒤 `NetworkConnection`이 `NetworkSendWorker`와 `NetworkRecvWorker` 전용 스레드를 각각 만든다. 연결 성공은 로그인이나 방 입장 승인을 의미하지 않는다.
- `GetConnectionState`와 `GetConnectionMessage`로 초기화 시점의 결과도 조회할 수 있다. 이후 변경은 `on_connection_state_changed_`로 전달한다.
- 연결 해제 시 대기를 해제하고 두 스레드 종료를 모두 기다린 다음 소켓과 송수신 큐를 파괴한다. 한쪽 오류는 양쪽 종료로 전달하며, 한 스레드만 생성된 경우에도 먼저 생성한 스레드를 정리한다. 재접속 때 이전 연결의 패킷을 재사용하지 않는다.

## 패킷 경계와 송신

- 기존 서버와 같은 little-endian 길이 2바이트와 종류 1바이트를 사용한다. 길이는 헤더를 포함하며 전체 패킷은 3~2048바이트다.
- `SendPacket(type, payload)`의 payload에는 헤더를 넣지 않는다. 종류 값과 본문 필드 배치는 기존 서버 정의를 따라야 한다.
- 반환값 true는 송신 큐에 접수했다는 뜻이다. 서버 수신이나 처리 완료를 보장하지 않는다. 큐 포화, 연결 종료, 크기 초과는 false다.
- 실제 송신은 송신 전용 스레드에서만 수행한다. 송신 큐에 패킷이 들어오면 이벤트로 즉시 깨우며 수신 대기와 독립적으로 진행한다. 부분 송신의 남은 바이트를 전송한 뒤 다음 패킷을 보낸다.
- 수신 전용 스레드는 도착을 기다리며 분할/합쳐진 패킷을 복원한다. 잘못된 길이나 수신 큐 포화는 연결을 종료한다. 송수신 큐는 각각 최대 1024개, 패킷마다 최대 2048바이트로 제한한다.

두 스레드는 같은 연결 소켓을 사용한다. 언리얼 소켓의 내부 상태 갱신 충돌을 막기 위해 비차단 송수신 호출만 잠깐 보호한다. 소켓 대기 중에는 잠금을 유지하지 않는다.

## 게임 스레드 처리

- 통신 스레드는 순수 바이트 데이터만 취급한다. UObject나 액터에 접근하지 않는다.
- `UNetworkWorldSubsystem`이 해당 게임 인스턴스의 현재 월드에서만 `OnWorldTickStart`에 수신 큐를 소비한다. 월드 액터 Tick보다 먼저 실행된다.
- `RegisterPacketHandler(type, FNetworkPacketHandler::CreateUObject(...))`로 패킷 종류별 처리 함수를 등록한다. 함수는 `const TArray<uint8>& payload`를 받는다.
- 중복 등록은 false를 반환한다. 월드에 속한 처리 객체는 종료 시 `UnregisterPacketHandler`를 호출한다. 객체 수명이 끝날 수 있는 경우 raw 포인터를 캡처하지 않고 약한 객체 바인딩을 사용한다.
- 등록되지 않은 종류는 소비 후 무시한다. 각 처리 함수는 본문 길이와 필드 값을 검사한 후 게임 상태에 적용해야 한다. `UOnlineSessionSubsystem`에 로그인·로비·방 패킷 처리 함수를 등록한다.
- 기본 처리 제한은 프레임당 128개 또는 2ms다. 시간 제한은 패킷 사이에서 확인하므로 개별 처리 함수 실행을 중간에 멈추지는 않는다.
- 처리 함수에서 연결을 끊거나 바꾸면 현재 배치를 즉시 끝낸다. 연결 해제 직전에 이미 수신한 정상 패킷은 순서대로 전달한 뒤 종료 상태를 알린다.
- 연결/송신/처리 함수 등록과 해제는 모두 게임 스레드에서 호출한다.

## 로그인·로비·방 연동

- `UOnlineSessionSubsystem`이 플레이어 정보, 방 목록, 현재 방과 참가자 정보를 보관한다. 각 화면 상태가 요청을 전달하고 변경 통지를 받아 기존 위젯을 갱신한다. 수신 정보에 따른 화면 갱신은 프레임당 한 번으로 모은다.
- `game_protocol.h`는 `Server/Packets`, `Server/Common`의 정의를 사용한다. 헤더를 제외한 본문을 송신 큐에 넣으며 수신 본문은 해당 패킷 크기를 검사한 뒤 읽는다. 서버의 패킷 정의 변경 시 양쪽을 함께 빌드해야 한다.
- 일반 로그인은 현재 서버가 기존 테트리스 데이터베이스에서 인증한 결과를 기다린다. 연결이 없으면 로그인 버튼으로 설정된 주소와 포트(기본 12312)에 재접속한다. 비밀번호는 화면 제출 후 비우며 계정 상태에 보관하지 않는다.
- 로비는 서버 방 목록 조회·새로고침, 공개·비공개 방 생성·참가, 빠른 시작을 처리한다. 빠른 시작은 클라이언트 목록을 선택하는 대신 서버 매칭 요청을 보낸다. 목록 새로고침은 테트리스처럼 기존 목록을 비우고 수신한 방을 추가한다.
- 방은 입퇴장, 준비·취소, 방장 변경, 강퇴, 시작 통보를 반영한다. 방장은 다른 참가자 행을 우클릭해 `강퇴`를 선택한다. 정원은 20명, 시작 조건은 최소 2명과 방장 외 전원 준비다.
- 상태가 바뀌는 요청은 응답 전까지 중복 송신하지 않는다. 서버 오류는 해당 화면에 표시한다. 20초간 응답이 없으면 연결을 종료해 늦은 성공 응답이 다음 요청에 섞이지 않게 한다.
- 서버 시작 통보 후 게임 맵으로 이동하고 로드가 끝나면 플레이 상태가 된다. 연결 종료 시 온라인 정보를 비우고 로그인 화면으로 돌아간다.
- 로컬 테스트 로그인은 기존처럼 서버 없이 동작하며 이동·동작 동기화는 하지 않는다.

## 이동·동작 동기화

- `UMovementSyncSubsystem`이 온라인 게임 레벨에서만 동작한다. 로컬 모드와 로그인·로비 레벨에서는 패킷 처리 함수를 등록하지 않는다.
- 내 캐릭터의 위치, 속도, 몸 방향, 시선 상하, 이동 입력, 공중 여부, 조준, 무기를 `MOVE_SEND_INTERVAL_MS`마다 `C2S_MOVE`로 보낸다. 이동 입력·점프와 착지·조준·무기 변화는 간격 제한 없이 즉시 `C2S_MOVE_INPUT`으로 보내고, 이동 방향이 크게 꺾이면 `MOVE_EXTRA_SEND_INTERVAL_MS`를 두고 보낸다.
- 휘두르기·줍기는 `C2S_ACTION`, 재장전은 `C2S_RELOAD`, 장비 교체는 `C2S_EQUIP`으로 동작 시각과 함께 보낸다. 서버는 동작 시각 순서를 확인하고, 장비 교체 대기(`EQUIP_DURATIONS_MS`) 중의 발사·휘두르기·재장전과 줍기 동작 중의 줍기를 받지 않으며, 조준 중에는 장비 교체를 받지 않는다. 클라이언트도 같은 조건으로 막는다.
- 재장전은 클라이언트가 바로 시작해 보이고, 끝은 서버의 `S2C_RELOAD_DONE`으로만 맺는다. 서버가 인정하지 않으면 지금 탄약으로 끝을 바로 보낸다. 장비를 바꾸면 재장전은 취소된다. 탄창이 비거나 빈 무기로 바꾸거나 탄을 얻었을 때의 자동 재장전은 서버가 시작해 `S2C_RELOAD`로 알린다.
- 곡괭이 사용 횟수는 서버가 휘두르기마다와 1번이 찰 때 보내는 `S2C_PICKAXE_CHARGES`로만 바뀌고, 남은 충전 시간은 표시만 센다.
- F키 상자 열기는 `C2S_BOX_OPEN`에 카메라 위치와 보는 방향을 담고, 서버가 시선이 그 상자의 상호작용 범위(`HINT_BOX_INTERACT_SCALE`)에 닿고 카메라에서 보였는지 확인한다.
- 발사는 `C2S_FIRE`로 퍼지기 전 조준 방향, 카메라 위치, 동작 시각을 보낸다. 동작 시각은 게임 레벨에 들어올 때 받은 `S2C_TIME_SYNC`의 서버 시각에 받은 뒤 흐른 실제 시간을 더한 값이고, 발사 간격도 같은 실제 시간으로 센다. 빗나감과 명중(다른 플레이어·선물·나무 상자·지형)은 서버가 판정하고, 클라이언트는 발사 동작과 소리만 보인다.
- 서버는 방 틱마다 중계할 이동 상태를 `S2C_MOVE` 하나로 묶고 그 틱의 `S2C_ACTION`을 이어 붙여 방 전원에게 보낸다. 입력 변화와 위치는 받은 틱에 바로 중계한다. 자기 상태는 클라이언트가 거른다.
- 처음 받은 플레이어는 내 캐릭터와 같은 클래스로 조종자 없이 생성하고 `URemoteMovementComponent`를 붙인다. 받은 입력으로 로컬 이동을 계산하고, 새 좌표를 받으면 캐릭터 위치와의 차이를 보간 이동으로 메운다. 차이가 크면 바로 옮긴다.
- 서버가 이동 상태가 끊긴(`MOVE_STOP_DELAY_SECONDS`) 플레이어나 이동을 되돌린 플레이어를 `S2C_MOVE_STOP`으로 알리면 그 캐릭터의 이동 입력을 0으로 둔다. 이동 상태가 다시 오면 서버가 이동 키 입력을 다시 중계한다.
- 동작은 판정 없이 애니메이션만 재생한다. 방 참가자에서 빠진 플레이어의 캐릭터는 제거한다.
