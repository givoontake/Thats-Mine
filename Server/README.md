# GameServer

Windows 서버 빌드에는 Visual Studio 2022 C++ 도구, CMake 3.21 이상, oneTBB, Botan, MySQL Connector/C++의 JDBC 라이브러리가 필요하다.

저장소 루트에서 아래 명령으로 빌드한다. 라이브러리 경로는 설치 위치에 맞춰 지정한다.

```powershell
cmake -S Server -B Server/Build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="C:/vcpkg/installed/x64-windows" -DMYSQL_CONNECTOR_ROOT="C:/Program Files/MySQL/MySQL Connector C++ 9.5"
cmake --build Server/Build --config Release --parallel
```

실행 파일과 필요한 동적 라이브러리는 `Server/Build/Release`에 생성된다. Debug 구성은 마지막 명령의 `Release`를 `Debug`로 바꾸면 된다.

## 현재 범위

- 방은 `GameRoom` 하나이며 정원은 `MAX_ROOM_PLAYER_COUNT = 20`으로 고정한다. 플레이어 20명 배열을 직접 보유한다.
- 공개·비공개 방 생성, 입장·퇴장, 준비·시작, 방장 변경·강퇴, 방 삭제 및 로비 복귀 흐름을 유지한다.
- 로비 세션 작업은 로비 스레드가, 방 소속 세션 작업은 해당 방 처리 스레드가 소비한다. 게임 틱과 작업 큐 소유권 구조는 기존과 같다.
- 테트리스 블록 처리, 점수·승패 계산, 관련 전용 패킷과 전적 조회·저장 기능은 제거했다. 방의 게임 틱 함수에는 아직 새 게임 규칙이 없다.
- 연결 직후에는 로그인 상태다. 기존 테트리스 데이터베이스의 `players` 테이블에서 계정을 조회하고 Botan의 bcrypt 검증을 통과한 뒤 로비로 전환한다. 플레이어 번호와 닉네임은 계정 정보를 사용하며 중복 로그인은 거절한다. 재접속 구분에는 기존 세션 세대 식별자를 사용한다.
- 유지한 방·로비 패킷의 번호와 배치는 기존과 같다. 사용하지 않는 단일 방 시작 패킷은 제거했고, 시작 통보는 기존 `S2C_MULTI_START`(39)를 사용한다. 방 참가자의 닉네임과 신규 입장자에게 보낼 기존 준비 상태를 전송한다. 생성자에게도 방장 정보를 보낸다. 클라이언트가 서버의 패킷 헤더를 함께 사용한다.
- 공개·비공개 방 생성 요청의 `max_player_count`는 20만 허용한다. 자동 매칭은 0(정원 무관) 또는 20을 받아 공개된 20인 대기방을 찾는다. 정원이 찬 방과 진행 중인 방에는 입장할 수 없다.
- 20명은 최대 정원이며, 시작 조건은 기존과 같이 최소 2명과 방장 외 전원 준비 완료다. 방장이 시작을 요청한다.

## 데이터베이스 연결

`Server/db_config.example.txt`를 `Server/db_config.txt`로 복사하고 접속 정보를 입력한다. 서버 작업 디렉터리를 `Server`로 설정하면 이 파일을 읽는다. 실제 설정 파일은 버전 관리에서 제외된다.

로그인 요청은 기존 구조대로 로그인 작업 큐 → 로그인 DB 스레드 → 완료 통지 → 세션 작업 큐 순서로 처리한다. 실제 계정 확인은 `LoginDBThread`에서 수행하고, `DBResultHandler`가 성공·실패와 중복 로그인을 처리한다. 연결이 끊겼거나 재사용된 세션에는 이전 로그인 결과를 적용하지 않는다.

`players`의 `login_id`, `password_hash`, `player_id`, `nickname`만 읽는다. 스키마 변경, 회원가입, 친구, 랭킹, 테트리스 전적 조회·저장은 추가하지 않는다. 기존 일반 DB 스레드는 연결만 유지한다. 설정 파일이 없거나 DB 연결에 실패하면 인증 요청에 오류를 반환하며 로비 입장을 허용하지 않는다.

로그인 패킷 번호는 기존 `C2S_LOGIN`(2), `S2C_LOGIN`(1)을 사용한다. 성공 응답에는 현재 게임에서 필요한 플레이어 번호와 닉네임만 포함하므로 테트리스 클라이언트의 전적 포함 응답과는 배치가 다르다. 현재 서버와 언리얼 클라이언트는 같은 정의를 사용한다.
